# 金庸群俠傳

開放式武俠角色扮演。你在揚州城外的官道上醒來，身無長物，要在江湖上湊齊十四部秘笈，最後上華山之巔。

**v3：一張圖的江湖。** 384×288、約 11 萬格的一層世界，沒有大地圖／城鎮之分——
走進襄陽是建物密度變高，不是載入另一個場景。海岸線、江河、山脈、官道、十五處街廓
全部是手寫的資料；荒野的草木沙石交給有種子的生成器填。唯一的第二層場景是建物內部。

線上版：**https://icomppower.github.io/jinyong-heroes/**

零依賴的純 ES 模組，沒有建置步驟。

```bash
npm run serve     # http://localhost:8123
npm run verify    # 數值驗證：連通性、高度、日夜、代價、主線可徒步通關（12 顆種子）
npm run smoke     # 無頭瀏覽器實際按鍵、走路、進屋、打完一場仗（兩幕）
npm run smoke https://icomppower.github.io/jinyong-heroes/   # 也可直接測線上版
```

## 玩法

- **走動**：方向鍵或 WASD，也可以直接點地圖上想去的地方自動尋路；畫面上另有一組方向鍵。
- **官道便宜，跨野貴**：沿官道走一天約一百二十格，跨野只有一半不到，上坡更慢更累。
  城鎮街道上逛街不耗體力也不推時辰。
- **日夜是系統不是濾鏡**：夜路遭遇率高、敵人略強，客棧深夜打烊——得算準天黑前趕得到哪，
  趕不到就地露宿。
- **高度**決定移動耗費與**視野**：站得高看得遠，而華山之巔就是全圖最高點，遠遠就看得見。
- **互動**：走上去撞到俠客就能邀他同行，撞到強敵就開打。掌櫃、店小二、靜室在建物裡，
  推開「門」字的門扉進去。沒有選單。
- **江湖自己會動**：官道上有商隊、鏢局押鏢、各派巡山弟子在走。追上商隊可以買藥。
- **渡海**：桃花島在東海上，走不過去，得在渡口搭船（半日腳程，船資十二兩）。
- **秘笈**：由強敵守著，打倒之後走過去撿。需**資質**足夠才學得會，每人至多十門，
  靠實戰精進到第十層。**內功**是被動的，直接抬高氣血、內力與攻防。
- **戰鬥**：方格戰棋。依輕功累積行動值出手，每回合可先移動再出一招。
- **同伴**：十八位可招募，多數看你集了幾部秘笈；也有看道德與聲望的。隊伍上限六人。
- **野球拳**照原作做成彩蛋——粗淺不堪，但練到第十層可與降龍十八掌抗衡。

除錯參數（給煙霧測試用，正常遊玩不會碰到）：
`?pos=x,y` `?at=地點id` `?time=時` `?books=N` `?gold=N` `?cam=視野格寬`。

## 結構

```
src/data/world/  jianghu 地理拓樸（手寫）· locations 各地玩法設定
src/data/        skills 武功 · items 物品 · chars 人物 · interiors 建物內部樣板
                 maps 世界建構（拓樸手寫，貼圖生成）
src/core/        rng 確定性亂數 · rules 數值規則 · field 走動與尋路 · battle 戰棋引擎
                 ai 戰鬥 AI · game 江湖狀態機（時辰、日夜、進出、渡海）
src/ui/          app 主控與面板 · sceneui 世界行走 · battleui 戰鬥畫面
tools/           verify.mjs 數值驗證 · uismoke.mjs + uitest.js 介面煙霧測試
```

`src/core/` 與 `src/data/` 完全不碰 DOM，Node 可直接載入——連通性、平衡、通關性全在無頭環境驗證。
從 v2 改成一層世界時，**戰棋引擎與數值規則一行沒動**。

## 為什麼地圖改成手寫的

v2 的地圖是程序生成的，`verify` 抓到的三個大缺陷全是生成器的產物：官道直接穿過城門、
襄陽的 NPC 圍成一圈把中間五格封死、大地圖淨空地形的迴圈邊界少清了最外圈。

改成資料之後，這一整類問題不存在了，`verify` 也從「找生成器的漏洞」升級成「驗設計意圖」。
真正手寫的大約三百個資料點：海岸線、江河折線、山脈脊線、官道的路口、十五個街廓的錨點、
每一棟建物的擺位；其餘交給有種子的生成器。分界是 **拓樸手寫，貼圖生成**。

## 驗證是怎麼做的

`tools/verify.mjs` 裡有一個**真的用走的**通關機器人：它在世界上尋路、走進城、推門進商鋪
撞掌櫃買藥、撞俠客入夥、搭船去桃花島、撞頭目開打、走過去撿秘笈，輸了就回城補給再練級重來。
跑十二顆種子，逐關輸出「平均嘗試次數／當時等級／第幾天」的難度表。所有數值都是照那張表改的。
最終曲線：3 → 26 級，沒有任何一關平均超過 2.5 次，華山之巔是全程最高峰。

v3 期間它抓到的（每一個都是真缺陷）：

- **一張圖之後，`type === 'boss'` 會同時命中十四個頭目**——機器人在揚州接到的指令，
  變成從揚州出發去走光明頂。所有實體因此都帶上所屬地點，述詞一律要指名是哪一處的。
- **官道在街廓裡照樣鑿路，把民宅切開一個洞**，門於是有了三個鄰格，不再是死路端點。
  → 進了街廓地面本來就是街道，官道不必再鑿；只有城牆該讓路，那一格就是城門。
- **一塊石碑塞住了無量山瑯嬛玉洞的洞口**，洞裡十格走得進去卻出不來。
  這正是 v2 襄陽那個 bug 的變形，只是這次兇手不是 NPC 而是路標。
  → 所有實心物件改成統一走一條「擺上去必須剛好只少一格走得到的地方」的擺位流程。
- **桃花陣種成了棋盤格**——四鄰接下，棋盤格的空格彼此並不相鄰，竹林反而把人困死。
- **渡口的碼頭蓋在民宅上**，把屋牆換成了沙地。地標蓋章一律改成不准動到建物。
- **兩台商隊一前一後就能堵死揚州城門**，而它們單獨站的每一格都不是割點——
  靠挑站位是防不住的。→ 會走動的 NPC 根本不當牆：走上去是「追上了他們」，尋路也不理會它們。
  站著不動的人則另外斷言「沒有任何一位站在割點上」。
- **秘笈未齊時，尋路照樣把華山之巔當近路**，排出一條走到一半被擋下來的路。
  → 尋路要知道哪裡進不去。

v1／v2 時期抓到的仍然有效：開場一人打三個潑皮必敗；主角經驗被同伴分掉，練到破關只有十級；
武當山的隨機遭遇比該地頭目還強，做出死亡螺旋（於是有了「**雜兵一律不得強過該地頭目**」這條斷言）；
請齊高手之後中後期連續八關都是 1.00 次過關——**等級單調上升不等於難度有起伏**，
所以另外斷言每關的平均嘗試次數。

`tools/uismoke.mjs` 用無頭 Chrome 跑兩幕：第一幕從標題畫面玩起，真的按方向鍵、點畫面方向鍵、
點地圖尋路、走進揚州、推門進商鋪買藥、撞人開對話、打完一場仗、撿起秘笈、露宿到天亮；
第二幕用除錯參數直接落在華山山道上，驗夜裡的遭遇率、鎖定視野，以及十三部秘笈上不去、
十四部就上得去。斷言的是數字不是截圖。

它抓到過三個純邏輯測試看不到的問題：`closeModal` 先清空 innerHTML 導致玩家取的名字永遠被丟掉；
`z-index` 疊錯讓對話框開在標題底下（玩家永遠進不了遊戲）；走路節奏綁在 `requestAnimationFrame`
上（背景分頁或無頭虛擬時間下不會跑）。

> `element.click()` 會直接把事件派給節點，**無視它是否被別的東西蓋住**，
> 所以測試裡另外用 `elementFromPoint` 斷言「這顆按鈕真的是它自己中心點上最上層的東西」。
> 驗證這種回歸測試有沒有用的方法：**先把 bug 改回去，確認測試會紅**，再修好確認轉綠。
