# 金庸群俠傳

開放式武俠角色扮演。你在揚州城外的官道上醒來，身無長物，要在江湖上湊齊十四部秘笈，最後上華山之巔。

**這是一個用走的江湖**：一張 130×96 的大地圖，官道縱橫，城鎮山門散在四方。
走到城門前踏進去，裡頭是可以逛的街市；走上去撞到人，就是跟他說話。

線上版：**https://icomppower.github.io/jinyong-heroes/**

零依賴的純 ES 模組，沒有建置步驟。

```bash
npm run serve     # http://localhost:8123
npm run verify    # 數值驗證：地圖連通性、戰鬥平衡、主線可徒步通關（12 顆種子）
npm run smoke     # 無頭瀏覽器實際按鍵、走路、打完一場仗
npm run smoke https://icomppower.github.io/jinyong-heroes/   # 也可直接測線上版
```

## 玩法

- **走動**：方向鍵或 WASD，也可以直接點地圖上想去的地方自動尋路；畫面上另有一組方向鍵。
- **互動**：走上去撞到掌櫃就開商鋪，撞到俠客就能邀他同行，撞到強敵就開打。沒有選單。
- **秘笈**：由強敵守著，打倒之後走過去撿。需**資質**足夠才學得會，每人至多十門，靠實戰精進到第十層。
- **內功**是被動的，直接抬高氣血、內力與攻防——所以打坐練功是真的有用。
- **戰鬥**：方格戰棋。依輕功累積行動值出手，每回合可先移動再出一招。
- **同伴**：十八位可招募，多數看你集了幾部秘笈；也有看道德與聲望的。隊伍上限六人。
- **野球拳**照原作做成彩蛋——粗淺不堪，但練到第十層可與降龍十八掌抗衡。

## 結構

```
src/data/    skills 武功 · items 物品 · chars 人物 · world 地點設定 · maps 地圖生成
src/core/    rng 確定性亂數 · rules 數值規則 · field 走動與尋路 · battle 戰棋引擎
             ai 戰鬥 AI · game 江湖狀態機
src/ui/      app 主控與面板 · sceneui 場景行走 · battleui 戰鬥畫面
tools/       verify.mjs 數值驗證 · uismoke.mjs + uitest.js 介面煙霧測試
```

`src/core/` 與 `src/data/` 完全不碰 DOM，Node 可直接載入——地圖、平衡、通關性全在無頭環境驗證。

## 驗證是怎麼做的

`tools/verify.mjs` 裡有一個**真的用走的**通關機器人：它在大地圖上尋路、進城、撞掌櫃買藥、
撞俠客入夥、撞頭目開打、走過去撿秘笈，輸了就回城補給再練級重來。跑十二顆種子，
逐關輸出「平均嘗試次數／當時等級／第幾天」的難度表。所有數值都是照那張表改的。

它抓到的都是真缺陷，不是小 bug：

- 開場一人打三個潑皮必敗；主角經驗被同伴分掉，練到破關只有十級。
- 武當山的隨機遭遇比該地頭目還強，等級不夠就連練級的路都被自己堵死
  → 立了「**雜兵一律不得強過該地頭目**」這條規則並寫成斷言。
- 官道直接穿過城門，沿路走會被硬拉進每一座城；尋路也會半路被傳走
  → 改成道路在路口交會，城門是往北退一格的死路端。
- 襄陽城的 NPC 圍成一圈把中間五格封死，走進去就出不來
  → 擺放 NPC 時強制檢查全圖連通，並加上「任一站得上去的格子都必須走得回出口」的斷言。
- 大地圖淨空地形的迴圈邊界寫成 `-3..3` 卻用 `≤4` 判斷，最外圈沒清到，
  出生點正好卡在邊上，往南是塊石頭——開場往下走不動。

`tools/uismoke.mjs` 用無頭 Chrome 真的按方向鍵、點畫面方向鍵、點地圖尋路、
走進城、撞人開對話、打完一場仗、撿起秘笈，斷言的是數字不是截圖。
它抓到過兩個純邏輯測試看不到的問題：`z-index` 疊錯讓對話框開在標題底下（玩家永遠進不了遊戲），
以及走路節奏綁在 `requestAnimationFrame` 上（背景分頁或無頭虛擬時間下不會跑）。

> `element.click()` 會直接把事件派給節點，**無視它是否被別的東西蓋住**，
> 所以測試裡另外用 `elementFromPoint` 斷言「這顆按鈕真的是它自己中心點上最上層的東西」。
