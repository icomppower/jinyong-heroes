# 金庸群俠傳 — v3D

第一人稱、只靠走的 3D 開放世界武俠。你在揚州城外的官道上醒來，最西是光明頂，最東是桃花島，
而全圖最高的那一點是華山之巔。**不騎馬、不衝刺、不開地圖**——認得出山，才走得到。

線上版：**https://icomppower.github.io/jinyong-heroes/**

**這一期只做世界，不做遊戲。**戰鬥、NPC、商鋪、秘笈、體力、天數、建物內部都不在這一期裡；
它們的規則仍然完整地活在 `src/core/` 與 `src/data/`（`npm run verify` 87 項照樣全綠），
只是還沒接上三維的表面。2D 俯視版（v3）已經整個移除，保存在 tag `v3-2d`。

零依賴的純 ES 模組，沒有建置步驟。

```bash
npm run serve       # http://localhost:8123
npm run verify      # 87 項：2D 的資料完整性、平衡、主線可徒步通關（一行未改）
npm run verify:3d   # 74 項：高度場、官道坡度、可走遮罩、通過條件、視線、步速
npm run smoke       # 無頭瀏覽器：真的建世界、真的畫、真的自走上華山
npm run smoke https://icomppower.github.io/jinyong-heroes/   # 也可直接測線上版
```

## 尺度：一格 = 2 公尺

格陣 384×288 **一格不動**——拓樸、`verify`、平衡表數的都是格，不是公尺。改的只有渲染時一格多大。
一格 2 公尺於是給出 768×576 公尺的世界：一格恰好是一個人站的地方，一棟房子 4–6 格約十公尺寬，
東西橫跨全圖約九分鐘實時步行。（取十公尺就是四十五分鐘，那就非得配馬不可——這正是不取十公尺的理由。）

## 操作

| | |
|---|---|
| `W A S D`／方向鍵 | 走 |
| 滑鼠（點畫面鎖定指標） | 看向 |
| `←` `→` 或 `Q` `E` | 轉身（不鎖指標也能玩） |
| `N` | 推三個時辰 |
| `H` | 收起提示 |

觸控：左半邊推著走，右半邊拖著看。

除錯參數：`?pos=格x,格y[,朝向]`、`#at=公尺x,公尺z[,朝向]`、`?time=時`、`?debug`。

## 架構

```
src/data/           那張已經驗過 87 項的圖（一行未改）
src/core/           規則、戰棋、狀態機（一行未改，這一期沒接上）
src/world3d/field.js       場：高度、官道、可走遮罩、視線、步速 — 不碰 THREE，Node 直接跑
src/world3d/kit.js         零件庫：六種屋頂、馬頭牆、燕尾脊、城牆、塔
src/world3d/scenery.js     地形網格、水、路面、石階、散佈
src/world3d/settlements.js 十五處聚落（從格陣長出來的）＋四個英雄輪廓
cities/jianghu.js          CITY 模組：江湖 = Golden Hour 的第六座「城市」
engine.js                  vendored golden-hour-engine ＋ runWalk（第一人稱）
```

`field.js` 對三維這邊，就是 `src/core/` 對 2D 那邊的位置：**算得出答案的那一半不進瀏覽器**。
所以「華山之巔是不是全圖唯一最高點」「官道坡度有沒有超過三成」「從揚州看不看得見華山」
全部是 `node tools/verify3d.mjs` 一行跑完的事。

## 通過條件（唯一的、可否證的）

**在揚州出生，第一人稱走到華山之巔。不准傳送、不准開小地圖。**

`tools/uitest.js` 讓走路機器人沿「最快走法」自走，用的是玩家同一套步速與碰撞，
不是另外寫一條捷徑。目前：**428.7 公尺，抵達峰頂 1.4 公尺內，海拔 96.6，全程 0 秒卡住。**

數字（`verify3d`）：華山之巔 96.9 公尺、全圖嚴格唯一最高點；官道最大坡度 0.233；
出生點到峰頂 520 公尺、約七分鐘、其中 73% 在官道上；一百二十公尺外 14/15 個取樣點看得見華山。

> ⚠️ 通過條件**不是**「看起來好不好」。那是不可滿足的退出條件，會讓迭代跑不完。

## 引擎：Golden Hour 加一個步行鏡頭

不另開 3D 引擎。`engine.js` 是 `icomppower/golden-hour-engine` 的 vendored 副本，
`runCity()`（開車的）原封不動留著，底下加一個 `runWalk()`。
**`./sync.sh` 會把 `runWalk` 蓋掉，要重新貼回去。**

直接取用、沒有重寫的：`makeHillRoad`（手置折線→採樣地形→平滑並限坡→Catmull-Rom 重採樣→
走廊內混向，這就是華山山道）、`FLATS` 圓角矩形 SDF 整平街廓、依所在地決定型別的建物造型、
`#at=` 深連結。不借的是 golden hour 那層夕陽光與無後果的兜風手感。

## 建築：遠看認得出來

低面數、instanced 幾何下真正傳遞得了訊息的只有四項：**屋頂形、山牆輪廓、顏色區塊、量體堆疊**。
六種屋頂蓋完全場（廡殿／歇山／懸山／攢尖＋馬頭牆／燕尾脊），時代取明中期當官方圖式，
只在大理把屋面凹曲轉向「更古」。**全圖沒有黃瓦**——黃色琉璃瓦專屬皇家，越用是僭越。
紅牆碧瓦只給武當，因為武當是明廷出錢蓋的，一眼就說完「這個門派有朝廷背景」。

四個手建的英雄輪廓：少林塔林（56 座，一到七層）、大理三塔、武當殿宇逐台而上＋山頂鎏金金殿、
襄陽城牆（收分、垛口、馬面、甕城）。

> ⚠️ 削預算先削塔林數量，**不要削屋頂種類**——屋頂一少，整個識別系統就塌了。

## 這一版抓到的真缺陷

- **街道代價是 0，拿來當步速的分母就是 Infinity。**2D 裡「城裡逛街不推時辰」寫成 `m: 0`；
  三維照抄去除，一步位移無限大，碰撞判定當然不給過，人就永遠釘在揚州南牆上。
  自走機器人第一次跑走了 11 公尺、卡了 920 秒。**凡是從別層借來的數值，都要問它有沒有零。**
- **只照格子判可走，玩家會直接爬崖。**華山山頂那片台地在格子上是「雪地，可走」，
  而它四周十四公尺內掉六十公尺。折返的山道於是白開。→ 三維的地面說了不算，格子也說了不算，
  **兩個都要點頭**：可走 = 格子可走 ∧ 坡度 ≤ 0.80。
- **一格寬的漢水會被抹平抹到不見。**高度場抹三次之後，河床的 −26 被兩岸的 +40 平均掉，
  浮到水面之上。→ 每一輪抹完重新把水格壓回去。
- **走廊蓋成方框，折返之間的縫會被填滿**，整面崖變成可走的，之字就白走了。→ 改用到中心線的距離。
- **山頂平台的邊緣會擋住它自己的峰頂。**平台抹到 250、峰岩 255，從遠處看只看得見平台邊。
  → 照 2D 那邊本來就有的封頂值 236：華山之巔是「一片台地上再立一塊七公尺高的岩」。
- **限坡迴圈磨不平最後一段**（端點每輪被釘回地面）。→ 石階改成照弧長把高度攤開，
  坡度恰好等於 爬升／路長，是算得出來的數，不是一個希望。
- **Chrome 第一次用新 profile 會跑 first-run 設定**，把第一幕整個吃掉而第二幕反而過。→ 先空跑暖機。

## 已知的讓步

- **桃花島徒步到不了**——渡海是唯一的非徒步移動，不在這一期。`verify3d` 把它斷言成「到不了」，
  不是讓它靜靜地失敗。
- **大理三塔壓到 30／19 公尺**（真高 69／42）。在 768 公尺見方的世界裡照實蓋會蓋過華山之巔，
  「華山是全圖最高」這條硬規則優先。比例照舊，絕對值讓步。
- **襄陽護城河沒做**。真寬 130–250 公尺，是湖不是溝；整座襄陽只有 68×52 公尺，照比例畫會把城淹掉。
- **無頭的 p95 幀時只證明「畫得出來」**，那是 SwiftShader 軟體算的。真的效能數字要在有 GPU 的機器上量。
